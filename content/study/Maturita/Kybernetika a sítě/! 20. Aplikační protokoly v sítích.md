
##### Co jsou aplikační protokoly ?
-  představují nejvyšší vrstvu modelu **OSI** (7. Aplikační vrstva)

- Jsou to pravidla, kterými se řídí výměna dat mezi klientem a serverem, přičemž jejich technické specifikace jsou definovány v dokumentech **RFC**.

# Dělení
### Klient server
- je síťová architektura, která odděluje **klienta** (často aplikaci s **grafickým uživatelským rozhraním**) a **server**, kteří spolu komunikují přes počítačovou síť
- klient žádá službu a server odpovídá
- protokoly:
	- **HTTP**/**HTTPS** - prohlížení webových stránek
	- **FTP** - přenos souborů
	- **SMTP**/**IMAP**/**POP3** - poštovní protokoly
	- **DNS:** Překlad doménových jmen na IP adresy.
	- **SSH:** Vzdálený přístup k serveru
- *Síť klient-server (obr.)*

#### Poštovní protokoly
- Struktura e-mailu
	- **Hlavička:** Obsahuje metadata (adresy odesílatele/příjemce, časové razítko, ID zprávy).
	- **Tělo:** Samotný obsah (formát `Plain text` nebo HTML, který činí e-mail vzhledově podobný webové stránce).
	- **Patička:** Zahrnuje přílohy a podpisy.
- E-mailová komunikace je komplexní proces využívající kombinaci několika protokolů pro odesílání, přenos a doručování zpráv. Na doručení e-mailu se podílí tři typy programů: MUA, MTA a MDA.
	- **MUA** (Mail User Agent )
		- Jedná se o poštovního klienta který zprostředkovává komunikaci mezi uživatelem a poštovním serverem (IMAP – synchronizace), a mezi klientem a počítačem a uživatelem POP3) 
		- Outlook, Thunderbird 
	- **MTA** (Mail Transfer Agent)
		- Slouží pro přesun pošty mezi servery a mezi serverem a počítačem 
	- **MDA** (Mail Delivery Agent )
		- Slouží k doručení pošty do příslušné poštovní schránky 
		- Dovecot
	
**Protokoly**:
##### SMTP (Simple Mail Transfer Protocol)
- **Porty:** 
	- 25 (nešifrovaný)
	- 587 (šifrovaný)
	- 465 (SMTPS)
- **FUNKCE**
	- Protokol určený výhradně pro **odesílání e-mailů**. Funguje jako „poštovní doručovatel“, který přenese zprávu od odesílatele k cílovému poštovnímu serveru (klient -> server )
	- navržen pro odchozí poštu 
	- používá protokol TCP/IP
-  **Pro bezpečnost využívá jedenu z těchto věcí:** 
	- STARTTLS 
		- Rozšíření protokolu umožňující povýšit nešifrované spojení na šifrované pomocí [[TLS]].
	- **SMTPS**
		- SMTP přes SSL/TLS, které šifruje celou komunikaci od navázání spojení.
##### POP3
- **Porty:** 
	- 110 (nešifrovaný) 
	- 995 (šifrovaný)
- **FUNKCE**
	- Nejstarší poštovní protokol pro stahování pošty. Automaticky stáhne zprávy ze serveru do klientské aplikace a standardně je ze serveru smaže.
	- protokol pro stahování elektronické pošty do PC
	- pošta je vždy čitelná v počítači
- **Omezení**
	-  Nevhodný pro moderní práci na více zařízeních, protože neudržuje stav zpráv (přečteno/nepřečteno) napříč klienty.

##### IMAP4 (Internet Message Access Protocol)
- **Porty:** 
	- 143 (nešifrovaný) 
	- 993 (šifrovaný)
- **FUNKCE**
	- Moderní protokol pro synchronizaci pošty. Pošta zůstává na serveru a klient pouze zobrazuje její kopii. Synchronizace probíhá přes hlavičky zpráv; akce se projeví na všech zařízeních současně.
- **Požadavek**
	- Vyžaduje neustálé připojení k internetu pro správnou synchronizaci složek (např. `new` a `cur`).

#### Prohlížení webových stránek
- Zajišťují přenos webových stránek a souvisejícího obsahu, a komunikaci mezi prohlížečem (klientem) a serverem

**Protokoly**

##### HTTP (Hypertext Transfer Protocol)
- **Porty:** 
	- 80 (HTTP) 
	- 443 (HTTPS) - šifrovaný
- **FUNKCE**
	- Protokol pro přenos webových stránek založený na principu dotaz-odpověď. Pomocí rozšíření **MIME** přenáší libovolné typy dat.
		- **MIME** - Standard umožňující přenos různých typů souborů (obrázky, video, fotky) v rámci HTTP a e-mailu.
- **metody**: GET/POST/PUT/DELETE
- **Zpracování:**
	- **Server-side (PHP, ASP):** Kód se vykoná na serveru, klient dostane již hotové HTML.
	- **Client-side (HTML, JavaScript):** Kód se vykonává přímo v prohlížeči uživatele.
- **HTTPS** -  Zabezpečená verze využívající **TLS** *(indikováno zámečkem v prohlížeči).*
	- TLS (Transport Layer Security), moderní nástupce SSL zajišťující integritu a důvěrnost dat.

#### Přenos souborů
- Slouží k přenosu souborů mezi klientem a serverem.
**Protokoly**

##### FTP (File Transfer Protocol)
- **Porty:** 
	- 20 (přenos dat)
	- 21 (příkazy)
- **FUNKCE**
	- Protokol pro přenos souborů mezi klientem a serverem. Dnes je považován za zastaralý kvůli absenci šifrování.
-  ==klientská část== tvořena FTP klientem *(Filezilla, Total commander, cmd, web prohlížeč)* 
- ==serverová část== pomocí server *(Ceasar FTP, Cerberus FTP, Filezilla)*
- **Bezpečné varianty:** SFTP a FTPS

#### DHCP (Dynamic Host Configuration Protocol)
- **Funkce:** Dynamicky přiděluje prvky síťového rozhraní (IP adresa, maska, brána, DNS). IP adresy jsou zapůjčovány na dobu určitou.

- **Proces (DORA):**
	1. **Discover:** Klient (s výchozí adresou 0.0.0.0) vyšle broadcast pro hledání serveru.
	2. **Offer:** Server zašle nabídku konfigurace.
	3. **Request:** Klient požádá o konkrétní konfiguraci.
	4. **ACK:** Server potvrdí zápůjčku.
	5.  **APIPA:** Pokud DHCP server není dostupný, systém si přidělí adresu z rozsahu `169.254.1.0` až `169.254.254.255`.

##### DNS (Domain Name System)
- **Funkce:** Překládá doménový název na IP adresu.
	- ==hierarchický systém, který funguje jako „telefonní seznam internetu“==. Překládá lidsky srozumitelné doménové názvy (např. `google.com`) na číselné IP adresy (např. `142.250.181.196`),
- **Druhy DNS serverů:**
	- **Autoritativní:** Drží finální záznamy o doméně.
	- **Rekurzivní:** Hledá odpovědi pro klienty dotazováním jiných serverů.
	- **Root name servery:** 13 globálních serverů spravovaných **IANA**.
		- IANA - organizace spravující globální přidělování IP adres a doménových jmen.

# Typ přenosu dat 

 **TCP**
- Spolehlivý
- Používá: HTTP, FTP, SMTP
- klíčový, spolehlivý protokol transportní vrstvy (4. vrstva OSI), který zajišťuje bezchybný obousměrný přenos dat mezi aplikacemi v síti
- Před odesláním dat vytváří virtuální okruh (tzv. "three-way handshake").
- Přizpůsobuje rychlost odesílání dat kapacitě sítě, aby nedošlo k zahlcení příjemce.
- TCP se nejčastěji používá v kombinaci s protokolem IP, tvořící základní sadu internetových protokolů **TCP/IP**. 
- Používá se například v (Web, e-mail, stahování souborů)

**UDP**
- Rychlý, nespolehlivý
- Používá: DNS, DHCP, NTP
- je jednoduchý a rychlý komunikační protokol používaný v počítačových sítích k přenosu dat. Na rozdíl od známějšího protokolu TCP je UDP tzv. **nespojovaný** a **nespolehlivý** (bez záruky doručení).
- nenavazuje spojení (neprobíhá žádný „handshake“) a nečeká na potvrzení o přijetí dat. Díky tomu je přenos okamžitý a efektivní.
- UDP se nejčastěji používá například v (Streamování, DSN, telefonování přes internet, Online Hry)

# Bezpečnost v sítích a digitální stopa

Bezpečnost je řízena [[TERM:Firemní politika|Soubor pravidel, směrnic a řádů definujících přístup k datům, fyzické zabezpečení a pravidla pro uživatele v organizaci.]].

- **Digitální stopa:** Souhrn dat o aktivitě uživatele v kyberprostoru.
- **Úmyslná:** Sdílení obsahu, polohy a fotek.
- **Neúmyslná:** Data generovaná protokoly a cookies.
- **Doporučení:** Minimalizace stopy, používání VPN, využívání HTTPS a certifikovaných úložišť.
