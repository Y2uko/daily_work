**Co jsou návrhové vzory ?**
- určité **problémy se opakují** znovu a znovu. A někdo chytrý řekl: _„Pojďme si ty osvědčené způsoby řešení pojmenovat a zdokumentovat."
- Nemusíš vynalézt kolo pouze použiješ postup, který už někdo vymyslel
- každý vzor je pojmenované řešení na konkrétní typ problému

|Problém|Vzor|
|---|---|
|Potřebuji jednu sdílenou instanci|**Singleton**|
|Potřebuji vytvářet objekty bez `new` všude|**Tovární metoda**|
|Potřebuji skupinu pomocných funkcí|**Utility třída**|
|Potřebuji pevnou sadu hodnot|**Enum**|

# Interface

Nejdřív musíme pochopit **interface** — bez toho nedává Servant ani Messenger smysl.

---
## Co je interface (rozhraní)?

Představ si pracovní inzerát. Firma napíše:

> _"Hledáme řidiče. Musí umět: nastartovat auto, zastavit auto, zatočit."_

Firma **neříká jak** to má řidič dělat. Jen říká **co musí umět**. Jestli točí volantem rukama nebo nohama — to je jeho věc.

Interface v Javě je přesně tohle — **seznam věcí, které třída musí umět.** Bez vysvětlení jak.

```java
interface Ridic {
    void nastartuj();
    void zastav();
    void zatoc(String smer);
}
```

Třída pak řekne _„já tohle splňuju"_ slovem `implements`:

```java
class Truckar implements Ridic {
    public void nastartuj() { System.out.println("Brumm!"); }
    public void zastav()    { System.out.println("Skřííp..."); }
    public void zatoc(String smer) { System.out.println("Točím " + smer); }
}
```

Pokud třída `implements Ridic` ale nenaimplementuje všechny metody → **Java hodí chybu.** Smlouva musí být splněna celá.

# Návrhové vzory

## Servant
- Někdy se můžeme dostat do situace, kdy máme určitou skupinu tříd, kterým chceme přidat další funkčnost. Přímou implementací bychom ale tuto funkčnost museli zkopírovat do každé z nich.  
	- máme tedy možnost funkčnost vyčlenit do samostatné třídy, takzvaného servant (služebník).  
- Jedná se o idiom, není tedy zařazen mezi  "pravé" návrhové vzory

- je vlastně takovou přepravkou na metody, které obsluhují instance určité skupiny tříd. Služebník je samostatná třída, která obsahuje metody manipulující s instancemi původních tříd, takzvaných **obsluhovaných tříd**. Budeme-li chtít po nějaké obsluhované třídě splnit určitou úlohu (třeba plynulý posun - animaci), požádáme o tuto úlohu služebníka, kterému předáme **instanci obsluhované třídy**. Služebník pak bude s obsluhovanými třídami komunikovat přes nějaké rozhraní.  
	- Tímto rozhraním může být například `IMovable`, které poskytne metody `setPoint()` a `getPoint()`, abychom mohli objekt posouvat. Toto rozhraní musíme pochopitelně také implementovat všem třídám, se kterými bude služebník pracovat.  

- **Servant** je třída, která poskytuje společnou funkcionalitu pro více různých tříd — přes interface. Servant sám neví, koho obsluhuje. Ví jen, že ten objekt implementuje daný interface.

- 2 způsoby implementace servanta
	1. dotazujeme na určitou úlohu přímo obsluhované třídy **přes služebníka**. Služebníku musíme předat instanci obsluhované třídy. Obsluhovaná třída nemusí o služebníkovi vědět.  
	2. zavolá metodu služebníka **sama obsluhovaná metoda**. Uživatel tedy nemusí o služebníkovi nic vědět.  


## Generická třída

















**Shrnutí všech tří jednou větou:**
- **Servant** — jedna třída obsluhuje více různých tříd přes interface (uklízečka pro všechny místnosti)
- **Generické třídy** — jedna třída funguje pro libovolný typ pomocí `<T>` (krabice na cokoliv)
- **Messenger** — jednoduchý objekt, který jen přenáší data pohromadě (obálka s daty)
