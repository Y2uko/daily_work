# Singleton + Tovární metoda
## Singleton
- návrhový vzor  (obecné a osvědčené řešení často se opakujícího problému)
- umožňuje zajistit **globální přístup** k instanci (*objektu*) nějaké třídy.  
- Proč se používá ?
	 V programu někdy potřebujeme sdílet **jednu instanci** mezi několika bloky, objekty atd. aniž bychom ji museli stále předávat v konstruktoru.
		- **Konstruktor** = speciální metoda, která se zavolá při vytváření nového objektu
- Singleton řeší situaci, kdy chceš mít jednu sdílenou věc (třeba DB připojení) přístupnou odkudkoli v programu, aniž bys ji musel všude dokola předávat ručně.
- to dělá například pomocí příkazu `getInstance()` (tovární metoda Singletonu)

### Definice vzoru Singleton
- Vzor je tvořen třídou, která se stará o to, aby její instance existovala **jen jednou**.

- Jako první musíme uživateli **zakázat tvořit instanci**. Docílíme toho implementací **prázdného privátního konstruktoru**. Dále vytvoříme běžnou instanční proměnnou a do ní vložíme instanci, kterou chceme v programu sdílet. V našem případě tedy instanci databázového připojení.

- Nyní si třída vytvoří instanci sebe sama a tu uloží do **statické proměnné**. Instanci má takto ve správě třída a uživatel se k ní jinak než přes ni nedostane, protože ji nemůže vytvořit. Máme ji tedy zcela pod kontrolou. Instanci nastavíme samozřejmě jako **privátní** a také **pouze pro čtení**.Nakonec vytvoříme veřejnou metodu, přes kterou budeme zvenku k instanci přistupovat. Uvnitř instanci vrátíme.

- **Singleton znamená jedináček**, tedy instance, která nemá žádné sourozence.

```Csharp
public sealed class Singleton 
{ 
	private static readonly Singleton instance = new Singleton();         public Databaze databaze = new Databaze("host", "jmeno", "heslo"); 
  
	private Singleton() {} 
	public static Singleton VratInstanci() 
    {
	   return instance; 
	} 
  
}  
```

- Použití v programu: `Pripojeni pripojeni = Singleton.VratInstanci();`  

Ačkoli Singleton by měl každý programátor znát, určitě to **není ideální vzor pro předávání závislostí v aplikaci**. Pro své problémy je dokonce součástí [antipraktik STUPID](navrh/best-practices-pro-vyvoj-softwaru/stupid-spatne-praktiky-vyvoje-softwaru). Lepším vyřešením závislostí je vzor [Dependency Injection](navrh/architektury-a-dependency-injection).  
## Tovární metoda
- Návrhový vzor
- odděluje vytváření instance od samotného programu  
#### Jak to sakra funguje ? 

Představ si, že jsi v restauraci. Řekneš číšníkovi: **„Dám si pizzu."** Ty neříkáš, jak ji udělat, kdo ji udělá, jakou troubu použít. Prostě dostaneš pizzu.

Tovární metoda funguje stejně. Místo abys ty (kód) říkal `new Pizza()`, `new Burger()`, `new Salat()` — prostě zavoláš jednu metodu a ona ti vrátí to, co potřebuješ. Jak to vzniklo, tě nezajímá.

**Bez tovární metody** — ty jako kód musíš vědět vše:
```java
if (typ == "pizza")  jidlo = new Pizza();
if (typ == "burger") jidlo = new Burger();
// tohle píšeš VŠUDE v programu kde potřebuješ jídlo
```

**S tovární metodou** — zavoláš jednou a hotovo:
```java
jidlo = Restaurace.objednej("pizza");
// uvnitř metody je ten if, ale ty to neřešíš
```

> Proč je to užitečné?
> 	Bez tovární metody bys ten `switch/if` psal na každém místě v kódu, kde potřebuješ vytvořit jídlo.  Přidáš nový typ (třeba `Sushi`)? Musíš ho přidat na jednom místě – do tovární metody. Zbytek kódu se nemění.

Bez tovární metody bys ten `switch/if` psal na každém místě v kódu, kde potřebuješ vytvořit jídlo.  
Přidáš nový typ (třeba `Sushi`)? Musíš ho přidat na jednom místě – do tovární metody. Zbytek kódu se nemění.

**Jedno větné shrnutí pro maturitu:**

Tovární metoda je statická metoda, která místo tebe rozhodne pomocí `new`, jaký objekt vytvořit a vrátí ti ho — ty jen řekneš co chceš, ne jak to udělat.

# Enum
- výčtový typ = říkáš předem všechny možné hodnoty
- definuje pevnou množinu pojmenovaných konstant
- Java pak pohlídá, že nepředáš nic jiného. Každá hodnota enumu má automaticky `name()` (textový název) a `ordinal()` (pořadí od nuly).

## Proč se Enum používá a jak funguje ?

 "výčtový typ" znamená, že **vyčítáš** (vypíšeš) všechny možné hodnoty dopředu.

- Nejlepší analogie: semafor. Semafor může být jen **červená, oranžová, nebo zelená**. Nic jiného. Nemůže být "modrá" nebo "číslo 42". Ty hodnoty jsou dané a pevné.

- Přesně tohle je enum — říkáš Javě: _"tato věc může nabývat JEN těchto hodnot, nic jiného neexistuje."_

**Proč to nestačí řešit běžnými proměnnými?**
- Bez enumu bys barvu semaforu uložil třeba jako `String` nebo `int`:  
	- `String barva = "cervena"` — ale co když někdo napíše `"Cervena"` nebo `"red"`? Program to neodhalí.
	- `int barva = 1` — co znamená 1? A 2? Musíš si pamatovat.

- Enum tohle celé vyřeší — Java sama pohlídá, že nepředáš nic neplatného.---

**Co si z toho zapamatovat pro maturitu:**
